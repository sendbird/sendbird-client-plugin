# /sendbird-client:push-setup

Resolve every plugin-owned path below from `${CLAUDE_PLUGIN_ROOT}`. Where that variable is empty (Codex does not set it for shell commands), the plugin root is the folder two levels above this SKILL.md.
Resolve the platform agent with `bash "${CLAUDE_PLUGIN_ROOT}/tools/routing/route-agent.sh" <project-dir> code`. Hand work to that agent by calling the `Agent` tool once with the agent as Claude Code lists it: this plugin's name, a colon, then the name the router printed (for example `sendbird-client:sendbird-ios-agent`). In Codex, which has no `Agent` tool, run that agent's launcher skill instead (for example `$sendbird-client:sendbird-ios-agent`) and start the agent only as that skill says; it sets the model and settings the agent needs. Do not do the agent's part yourself, even in a small project: write or edit no project source file in this session, before or after the hand-off, also when the customer confirms a change in a later turn. If the hand-off fails, say that this part was not done. When the agent reports, your final answer carries its changed files, every check line, and its symbol, source, and version table as the agent wrote them (`docs/AGENT_CONTRACT.md` section 6); shorten the wording only.
Before anything else, check every product the request names (AI Agent, its messenger or launcher, is `ai-agent`; the others are `chat`, `uikit`, `calls`, `desk`, and `live`) with `bash "${CLAUDE_PLUGIN_ROOT}/tools/detection/resolve-products.sh" <project-dir> --check <product>`, one run per product. Printing the scope without `--check` is not this check. When it exits 1, change nothing and hand nothing to an agent: say what it printed. Only for "out of configured scope" add that `SENDBIRD_PRODUCTS` or `enabledProducts` in `.sendbird-client/profile.json` sets the scope; for "not available on this host" give the reason it printed and never suggest those settings, which cannot change it; a non-interactive run ends with `status: "declined"`.

Push end-to-end for the detected platform.

## Steps
1. Detect platform + push provider (Tier-2 detector) + products. Ask once if unknown. When the app already registers Sendbird push and the customer reports a symptom (no push, push twice, no push after the app is closed), follow "Diagnose a push symptom" below instead of these steps.
   - This skill never needs the App ID. Push code reads nothing from it, so an App ID that is empty or missing (in `project.yml`, a build setting, `profile.json`, or the environment) never stops this skill: do not read those yourself to judge it, do not ask for it, and do not end with `needs_input` over it (`docs/AGENT_CONTRACT.md` section 3; only setup asks). Go on to the hand-off in step 3. When `tools/detection/resolve-app-id.sh` reports `from: missing`, add setting the App ID to `manualSteps`.
   - Ask about the provider only when there is a choice, which is iOS (`apns-p8` or `apns-cert`). The iOS client code is the same for both: the app registers its APNs device token with Sendbird either way, and the choice only decides what the customer uploads on the dashboard (`knowledge/curated/ios/cross-cutting/push.md` "Setup checklist"). So the answer never blocks the code on it. Non-interactive (`SENDBIRD_NONINTERACTIVE`) on iOS: when the provider is `unknown` and the request names none, ask nothing; write the client code, and list the dashboard upload as a hand-off step with both branches, the `.p8` auth key and the certificate, each linked to the official dashboard push configuration guide as that checklist says.
   - On Android and React Native, do not ask, also in a non-interactive run. The detector's only Android value is `fcm` (`tools/detection/tier2/detect-push-provider.sh`), and Android push is set up with FCM (`knowledge/curated/android/cross-cutting/push.md` "Overview"). React Native registers an FCM token on Android and an APNs token on iOS (`knowledge/curated/js/cross-cutting/push.md` "Overview"). Take that path, and list the Firebase files and the dashboard credential upload as hand-off steps ("Setup checklist" in the same file).
2. React in a browser: stop here. Quote `knowledge/curated/js/cross-cutting/push.md` "Overview" (the Chat SDK has no browser push; a web app builds its own notifications from Sendbird webhooks) and change no files. Do not write a service worker, browser notification code, or web push registration. Alerts while a tab is open are a separate feature, handled by `add-feature` only when the customer asks for them.
3. Walk the provider path (APNS cert vs .p8 / FCM / React Native), cite the dashboard-config docs (do NOT invent dashboard click-paths), then hand off to the platform agent for token-registration + payload + deeplink code from the wired sources below. The hand-off is required on every host: in Codex, run the agent's launcher skill; a run that changed no file and never started the agent did not do this skill.
   On Android, apply the `com.google.gms.google-services` Gradle plugin only when `app/google-services.json` exists, and never create a placeholder file. An unconditional apply fails the build when the file is missing. When the file is absent, leave the plugin out (or apply it conditionally) and list "download `google-services.json` from your Firebase project into `app/`" as a customer hand-off step (`knowledge/curated/android/cross-cutting/push.md` "Setup checklist").
   An app started from `templates/starters-bp/` already has one registration point: register at the `BP10` comment and unregister at the `BP09` comment (search the project for them; its `_README.md` lists both when present), and add no second registration path. On React Native UIKit, connect already registers the token and disconnect unregisters it (`knowledge/curated/js/cross-cutting/push.md` "React Native UIKit: automatic token registration"): add no registration code, do not turn the automatic registration off, and leave only the Firebase files and credentials as hand-off steps.
   Android with the Compose UIKit (`uikit-compose`): register the push handler after init and again after connect, as `knowledge/curated/android/hosts/compose.md` "UIKit for Jetpack Compose — init, then push" shows.
4. Cover foreground/background, Android 13+ POST_NOTIFICATIONS, VoIP push when Calls is present.
   On logout, unregister the token before disconnecting, inside the app's existing sign-out or logout function; use the unregister call in `knowledge/curated/<platform>/cross-cutting/push.md`. A token left registered keeps sending the previous user's notifications to this device.
5. End with a test-message checklist.

## Diagnose a push symptom
For an app whose push is already set up, find the cause instead of setting push up again.
1. Pick the matching entry from the push section of `knowledge/curated/<platform>/cross-cutting/troubleshooting.md` ("Push" on iOS and JS, "Push notifications" on Android).
2. Read the app's token registration, handler registration, and notification code. For each cause the entry names, record the evidence as file:line with the code, or "not found", and say whether it is the cause.
3. Report the entry by its title, the cause with file:line, and only that entry's fix. Do not add setup the customer did not ask for (permission prompts, notification display code, logout unregistration).
4. Do not offer a cause that no entry names (for example battery optimization), even labeled as general knowledge. When no entry matches the evidence, say which entries you ruled out and with what evidence.

## Wired knowledge (populated and cited)
- Token registration: `knowledge/curated/<platform>/cross-cutting/push.md` — iOS `registerDevicePushToken`/`unregisterPushToken`/`unregisterAllPushToken` (build-verified); Android `SendbirdPushHandler` subclass + `SendbirdPushHelper.registerHandler(...)`; JS `registerFCM/APNSPushTokenForCurrentUser` + unregister variants (type-checked).
- Notifications not arriving: also read `knowledge/curated/<platform>/cross-cutting/troubleshooting.md` and answer with the API its matching entry names. For example, on Android a push that arrives in the background but never after the app is swiped away means init and handler registration run in an Activity instead of `Application.onCreate()`.
- VoIP for Calls: registered via the Calls SDK (`SendBirdCall.registerVoIPPush`) — the Chat SDK's PushKit method was REMOVED; see `knowledge/curated/ios/products/calls.md`. Do not emit the removed API.

## No-Fabrication
Token-registration APIs and payload keys must be verified + cited. Dashboard navigation is linked to docs, never reproduced from memory. A fact you cannot verify is left out and named as unverified; never add it with a label.
