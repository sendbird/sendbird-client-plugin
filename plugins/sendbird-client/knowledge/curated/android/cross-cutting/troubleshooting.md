# android — troubleshooting

> Symptom → cause → fix entries built from solved public cases (Sendbird community forum and GitHub discussions). Each fix was re-checked against the pinned SDK surface (`javap` of sendbird-chat 4.36.5, uikit 3.26.3, sendbird-calls 1.12.5 and sendbird-common 1.0.7) or against the published POM and CHANGELOG. Behavior that only a case states is attributed to that case. Answers written for Chat v3 or UIKit v2 were rewritten for the current API or dropped. Case links marked **community** were resolved by the poster or another user, not by Sendbird staff. Verified 2026-10-08. On 2026-10-12 the citations were moved to public sources: the Chat v4 Android API reference and docs on sendbird.com, the public UIKit Android source at commit `07ffe8e` (3.26.3), or the AAR class or manifest by name.

## Build and install

### Gradle can't resolve `com.sendbird.sdk:*` artifacts
- **Cause:** The Sendbird Maven repository is missing from the place Gradle actually reads repositories. Projects created with Gradle 7+ resolve dependencies from `dependencyResolutionManagement` in `settings.gradle(.kts)`.
- **Fix:** Declare `maven { setUrl("https://repo.sendbird.com/public/maven") }` inside `dependencyResolutionManagement { repositories { ... } }` in `settings.gradle(.kts)`, then sync. Opening that URL in a browser returns 404; that is expected and does not mean the repository is down. (source: knowledge/curated/android/setup.md — Packaging) (staff answer in the first case below)
- **Cases:** https://community.sendbird.com/t/cant-install-non-jcenter-sdk-versions/4670, https://community.sendbird.com/t/cant-use-https-repo-sendbird-com-public-maven/2480 — community

### App crashes on Android 15 devices with 16 KB memory pages, or the APK ships unexpected Conscrypt `.so` files
- **Cause:** Chat SDK versions before 4.25.0 pulled in `org.conscrypt:conscrypt-android` (2.2.1 per the first case) for TLS 1.3. Its native libraries are not built for 16 KB page sizes, and they add native code to every ABI split.
- **Fix:** Upgrade to Chat SDK 4.25.0 or later. Starting with 4.25.0 the SDK no longer includes Conscrypt, and the 4.36.5 POM depends only on `sendbird-common`, `sendbird-auth`, `kotlin-stdlib` and `androidx.annotation`. Run `./gradlew :app:dependencies` to confirm nothing else still brings in an old Conscrypt. If you use UIKit, declare the newer Chat SDK explicitly (see setup.md). Add `conscrypt-android` back yourself only if you need TLS 1.3 on Android 9 or lower, and pick a release whose native libraries support 16 KB pages (the workaround in the first case forced 2.5.3). Without Conscrypt the SDK logs `Couldn't locate conscrypt dependency from your build.gradle`; the log itself says this is safe to ignore. (source: https://github.com/sendbird/sendbird-chat-sdk-android/blob/main/CHANGELOG.md — v4.25.0) (source: https://repo.sendbird.com/public/maven/com/sendbird/sdk/sendbird-chat/4.36.5/sendbird-chat-4.36.5.pom) (source: sendbird-chat 4.36.5 AAR, log string in the class `com.sendbird.android.SendbirdChat`) (source: knowledge/curated/android/setup.md — Getting a newer Chat SDK under UIKit)
- **Cases:** https://github.com/sendbird/sendbird-chat-sdk-android/discussions/65, https://github.com/sendbird/sendbird-chat-sdk-android/discussions/63, https://community.sendbird.com/t/add-support-for-android-15-16kb-page-size-plus-workaround/10539, https://community.sendbird.com/t/native-libraries-in-build-after-sendbird-integration/3026

### UIKit shows only "Couldn't retrieve channel.", or creating a channel fails in some builds
- **Cause:** UIKit was never initialized, or the user was not connected yet. A typical case is an `Application` subclass that calls `SendbirdUIKit.init(adapter, context)` but is not registered with `android:name` in `AndroidManifest.xml`, so its `onCreate` never runs. Another is app code that calls Chat APIs, such as channel creation, before the connection completes.
- **Fix:** Call `SendbirdUIKit.init(...)` in `Application.onCreate` and register that class in the manifest. In your own screens, create channels only from the success callback of `SendbirdUIKit.connect(...)` or `SendbirdChat.connect(...)`; calling earlier fails with `ERR_CONNECTION_REQUIRED` (800101). (source: knowledge/curated/android/setup.md — Init) (source: https://sendbird.com/docs/chat/uikit/v3/android-view/essentials/authentication) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/SendbirdUIKit.java#L267 — `init` at line 267, `connect` at line 557) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/res/values/strings.xml#L118 — `sb_text_error_get_channel`) (source: https://sendbird.com/docs/chat/sdk/v4/android/error-codes) (source: knowledge/curated/android/cross-cutting/errors.md)
- **Cases:** https://community.sendbird.com/t/uikit-2-2-4-couldnt-retrieve-channel-toast/4650, https://community.sendbird.com/t/please-help-me-on-this/2382

### Manifest merger fails on a `FileProvider` (`provider@authorities` or `FILE_PROVIDER_PATHS`) after adding UIKit
- **Cause:** Older UIKit releases declared the plain `androidx.core.content.FileProvider` in their manifest, with the authority `${applicationId}.provider` and the paths file `@xml/sb_file_paths` (quoted from UIKit 2.1.5 in the first case). The manifest merger matches `<provider>` elements by `android:name`, so an app or another library that declared the same class collided with it (Sendbird staff explanation in the first case; the second case shows the same error with UIKit 3.3.3).
- **Fix:** Upgrade UIKit. The 3.5.4 release notes list "Improved FileProvider compatibility" (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/CHANGELOG.md#L338-L341). In 3.26.3 the AAR manifest declares its own class, `com.sendbird.uikit.model.SendbirdUIKitFileProvider`, with the authority `${applicationId}.sendbird.uikit.provider`, so it no longer shares a merge key with an app's `androidx.core.content.FileProvider` (source: uikit-3.26.3.aar AndroidManifest.xml lines 153-161).
- **Cases:** https://community.sendbird.com/t/sendbird-uikit-using-androidx-core-content-fileprovider-directly/2687, https://community.sendbird.com/t/fileprovider-manifest-merger-conflict-with-other-dependencies/6393

## Connection and auth

### `connect` fails with 400302, or a user who used to connect without a token is now rejected
- **Cause:** Either the session or access token expired or was revoked (`SendbirdError.ERR_INVALID_TOKEN`, 400302), or the user now has a token issued. According to Sendbird staff, once a token exists for a user, that user can no longer connect without one, even if the application allows token-less connections.
- **Fix:** Connect with a valid token issued by your server through `SendbirdChat.connect(userId, token, handler)`, and refresh it when it expires. Call `SendbirdChat.setSessionHandler(...)` before `connect`, and answer `SessionHandler.onSessionTokenRequired(requester)` with a fresh token from your server. (source: knowledge/curated/android/products/auth.md — Session token expiry) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android/-sendbird-chat/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.handler/-session-handler/index.html) (source: knowledge/curated/android/cross-cutting/errors.md — 400302) (source: https://sendbird.com/docs/chat/sdk/v4/android/error-codes)
- **Cases:** https://community.sendbird.com/t/400302-invalidaccesstoken/3003, https://community.sendbird.com/t/sdk-is-throwing-the-exception/4388, https://community.sendbird.com/t/how-to-login-sdk-without-token-after-using-token/10025

### `GroupChannel.getChannel(url)` fails with 400201, or a channel suddenly disappears
- **Cause:** 400201 (`SendbirdError.ERR_NOT_FOUND_IN_DATABASE`) means no channel matches that URL: the URL is wrong or the channel was deleted. By default, a group channel is deleted automatically when its last member leaves or is removed, so URLs your app stored for such channels stop resolving.
- **Fix:** Check that the URL is valid and that the channel still exists, for example in the dashboard. If your product needs empty channels to survive, ask Sendbird support to change that application setting; staff answers say it can't be changed from the SDK. Sendbird does not record client exceptions for you, so log them yourself. (source: https://sendbird.com/docs/chat/sdk/v4/android/channel/retrieving-channels/retrieve-a-channel-by-url) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.channel/-group-channel/-companion/index.html) (source: knowledge/curated/android/cross-cutting/errors.md — 400201) (source: https://sendbird.com/docs/chat/sdk/v4/android/error-codes) (staff answers in the cases below)
- **Cases:** https://community.sendbird.com/t/getting-channel-not-found-exception-error-code-400201/3614, https://community.sendbird.com/t/group-channel-is-automatically-deleted-when-the-number-of-users-reaches-0/10161, https://community.sendbird.com/t/all-channels-deleted/7299

## Messages and channels

### `getMessagesByTimestamp` returns messages you already have (duplicates)
- **Cause:** `getMessagesByTimestamp(ts, params, handler)` on a channel returns `previousResultSize` messages before the timestamp and `nextResultSize` messages after it. When `nextResultSize` is not 0, each backward page also returns messages newer than the timestamp, which are already on screen.
- **Fix:** When paging backwards, set `nextResultSize = 0` on the `MessageListParams` and set only `previousResultSize`. (source: https://sendbird.com/docs/chat/sdk/v4/android/message/retrieving-messages/retrieve-a-list-of-messages) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.channel/-base-channel/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.params/-message-list-params/index.html)
- **Cases:** https://community.sendbird.com/t/how-to-migrate-to-getmessagesbytimestamp-from-getpreviousmessagesbytimestamp-on-android/6356

### `getUnreadMemberCount` is always 0, or read receipts are missing
- **Cause:** The API reference says `getUnreadMemberCount` is always zero when the message is an `AdminMessage` or the channel is a Supergroup channel (`GroupChannel.isSuper` is true). The channel overview's feature table lists read receipts as not available in Supergroup channels.
- **Fix:** Check `message is AdminMessage` and `channel.isSuper` before showing read receipts or unread counts, and hide the receipt UI in Supergroup channels. (source: https://sendbird.com/docs/chat/sdk/v4/android/channel/overview-channel) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.channel/-group-channel/get-unread-member-count.html) (source: knowledge/curated/android/products/chat.md — Read receipts for a message)
- **Cases:** https://community.sendbird.com/t/in-android-groupchannel-unreadmemberscount-always-0/3049

### A channel created elsewhere (server, another client) doesn't appear in the UIKit channel list
- **Cause:** UIKit's channel list builds its query from a default `GroupChannelListQueryParams`, whose `includeEmpty` is `false`. A channel with no messages stays hidden until someone sends the first message.
- **Fix:** Pass your own query: `ChannelListFragment.Builder.setGroupChannelListQuery(GroupChannel.createMyGroupChannelListQuery(GroupChannelListQueryParams().apply { includeEmpty = true }))`. (source: https://sendbird.com/docs/chat/uikit/v3/android-view/customizations/channel-list-customization/filter-channel-list) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/vm/ChannelListViewModel.java#L296-L300 — `createGroupChannelListQuery()`) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/fragments/ChannelListFragment.java#L572 — `setGroupChannelListQuery`) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.params/-group-channel-list-query-params/index.html — `includeEmpty: Boolean = false`) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.channel/-group-channel/-companion/index.html)
- **Cases:** https://community.sendbird.com/t/sendbird-uikit-not-showing-private-chat/354

### UIKit creates a new 1:1 channel every time with the same user
- **Cause:** UIKit's create-channel screen sets `GroupChannelCreateParams.isDistinct` only when you ask for it. Otherwise the field stays unset and the server creates a new, non-distinct channel each time.
- **Fix:** Build the screen with `CreateChannelFragment.Builder.setIsDistinct(true)`. To apply it app-wide, register `SendbirdUIKit.setCustomParamsHandler(...)` and set `params.isDistinct = true` in `onBeforeCreateGroupChannel(params)`. With distinct on, creating a channel with the same members returns the existing one. (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/SendbirdUIKit.java) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/fragments/CreateChannelFragment.java#L171-L179 — `isDistinct` set only when the argument exists; `setIsDistinct` at line 450) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/interfaces/CustomParamsHandler.java#L28) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.params/-group-channel-create-params/index.html)
- **Cases:** https://community.sendbird.com/t/multiple-channels-with-same-user-being-created-from-new-channel-screen/7366

### Thread replies show up in the main UIKit message list
- **Cause:** When the UIKit reply type (`com.sendbird.uikit.consts.ReplyType`) is `QUOTE_REPLY` or `THREAD`, `ChannelViewModel.createMessageListParams()` loads the list with the Chat `com.sendbird.android.message.ReplyType.ONLY_REPLY_TO_CHANNEL`, so replies are included in the channel list (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/vm/ChannelViewModel.java#L1143-L1154).
- **Fix:** Keep the UIKit reply type as `THREAD` so the thread UI still works, and load the main list with the Chat `ReplyType.NONE`. Either pass your own `MessageListParams` (with `replyType = ReplyType.NONE`) through `ChannelFragment.Builder.setMessageListParams(...)`, which UIKit uses as given apart from forcing `reverse`, or override `createMessageListParams()` in a custom `ChannelViewModel`, as the staff answer does. (source: https://sendbird.com/docs/chat/uikit/v3/android-view/customizations/chat-customization/filter-message-list) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/consts/ReplyType.kt#L8) (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/fragments/ChannelFragment.java#L1585 — `setMessageListParams`) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.message/-reply-type/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.params/-message-list-params/index.html)
- **Cases:** https://github.com/sendbird/sendbird-uikit-android/discussions/38

### Messages look sent but are gone after leaving and reopening the channel
- **Cause:** The channel is ephemeral. The channel overview says messages in an ephemeral group channel aren't saved in Sendbird's database, so they can't be loaded again.
- **Fix:** Create channels whose history you need with `isEphemeral` left unset or `false` on `GroupChannelCreateParams`, and check `channel.isEphemeral` on existing ones. (source: https://sendbird.com/docs/chat/sdk/v4/android/channel/overview-channel) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.params/-group-channel-create-params/index.html)
- **Cases:** https://community.sendbird.com/t/message-appears-to-get-deleted-right-after-sending-it/1902 (an iOS app; the cause is the channel type, not the platform)

### Messages sent before a user joined are missing
- **Cause:** By default, a member sees only the messages sent after they joined the group channel. This is an application setting (chat history), not an SDK option. The cases below come from JavaScript apps; the setting belongs to the application and applies to every platform.
- **Fix:** Turn on chat history for group channels in the dashboard's channel settings. Per the cases, it applies to users who join after it is turned on.
- **Cases:** https://community.sendbird.com/t/error-calling-get-message-by-id-for-message-sent-before-user-joins-a-group-channel/9451, https://community.sendbird.com/t/getting-first-message-of-channel/9507, https://community.sendbird.com/t/chat-history-when-joining-private-group-channel/2237

### UIKit shows an image or video as a generic file
- **Cause:** UIKit picks the view from the file message's `type`, the MIME type sent in `mimeType`. Only a type that starts with `image` (except SVG) gets the image view, and only one that starts with `video` gets the video view; anything else, including an empty type, gets the generic file view. (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/java/com/sendbird/uikit/activities/viewholder/MessageViewHolderFactory.java#L291-L327)
- **Fix:** Set `mimeType` on `FileMessageCreateParams` to the file's full MIME type, such as `image/jpeg` or `video/mp4`. (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.params/-file-message-create-params/index.html) (source: knowledge/curated/android/products/uikit.md — Custom message views, including file messages)

### The keyboard covers the message input when the channel screen is inside your own Activity
- **Cause:** UIKit's own `ChannelActivity` is declared with `android:windowSoftInputMode="adjustResize|stateAlwaysHidden"`, so the window shrinks above the keyboard. An Activity of yours that hosts `ChannelFragment` does not get that declaration. (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/uikit/src/main/AndroidManifest.xml#L48-L51)
- **Fix:** Declare `android:windowSoftInputMode="adjustResize"` on that Activity in your manifest. Android's guide says `adjustResize` resizes the layout to the space left by the keyboard. (source: https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility)

### A `ChannelFragment` (or a subclass) shows no messages after you navigate back to it with the Navigation component
- **Cause:** In UIKit versions before 3.25.2, messages in `ChannelFragment` were not displayed after returning from another fragment when the app used the Navigation component. The 3.25.2 release notes list this as a fixed issue.
- **Fix:** Upgrade UIKit to 3.25.2 or later. (source: https://github.com/sendbird/sendbird-uikit-android/blob/07ffe8efc97e2d71dedc466ad868df817e5f433e/CHANGELOG.md#L15-L16 — v3.25.2)

## Push notifications

### No chat push arrives when the app is killed
- **Cause:** FCM wakes the app process without starting any Activity. If `SendbirdChat.init` and `SendbirdPushHelper.registerHandler(...)` run in a splash or main Activity, they never run for that push, so nothing handles it.
- **Fix:** Call `SendbirdChat.init(...)` and `SendbirdPushHelper.registerHandler(yourSendbirdPushHandler)` in `Application.onCreate`, and register the `Application` class in the manifest. (source: knowledge/curated/android/cross-cutting/push.md — Register the handler) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android/-sendbird-chat/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.push/-sendbird-push-helper/index.html)
- **Cases:** https://community.sendbird.com/t/push-notifications-android-in-kill-state/3814, https://community.sendbird.com/t/chat-push-notification/3687

### No device token is registered, or Sendbird pushes stop after adding another FCM library
- **Cause:** The Chat SDK already declares `com.sendbird.android.push.SendbirdFirebaseMessagingService` (and an HMS service) in its manifest. An app-declared `FirebaseMessagingService` that handles the same `MESSAGING_EVENT` competes with it, so token updates and messages may never reach Sendbird. `SendbirdPushHandler` is not a `Service`; it is a handler that the SDK's service calls.
- **Fix:** Remove your own FCM (or HMS) messaging service from the manifest, subclass `SendbirdPushHandler`, and register it with `SendbirdPushHelper.registerHandler(...)`. According to Sendbird staff, FCM messages from your other backends are also passed to that handler's `onMessageReceived`, so handle them there. If you register tokens manually instead, call `SendbirdChat.registerPushToken(...)` after `connect` succeeds. (source: knowledge/curated/android/cross-cutting/push.md) (source: sendbird-chat 4.36.5 AAR `AndroidManifest.xml`) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.push/-sendbird-firebase-messaging-service/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.push/-sendbird-push-helper/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android/-sendbird-chat/index.html)
- **Cases:** https://community.sendbird.com/t/uikit-android-push-notifications-no-device-token/3650, https://community.sendbird.com/t/fcm-hms-pushes-plus-sendbird-pushes/3807

### Push arrives in the background but not while the app is in the foreground
- **Cause:** `SendbirdPushHandler.alwaysReceiveMessage()` returns `false` by default, which the FCM setup guide says means push notifications are delivered only when the app is in the background. The API reference adds that the SDK drops a push payload when the app is in the foreground and connected, or when the same message already reached a channel handler's `onMessageReceived`.
- **Fix:** Show in-app alerts from your channel handler. If you really need a system push while online, enable "Send to devices both offline and online" under Settings > Chat > Push notifications in the dashboard (the FCM setup guide and the staff answer both name it), and override `alwaysReceiveMessage()` to return `true`. (source: knowledge/curated/android/cross-cutting/push.md — Handler-based vs manual token registration) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.push/-sendbird-push-handler/always-receive-message.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/push-notifications/multi-device-support/set-up-push-notifications-for-fcm)
- **Cases:** https://community.sendbird.com/t/fcm-push-notification-is-not-working-when-the-app-in-foreground/3969

### Push delivery or the dashboard test push fails with `MismatchSenderId` or `NotRegistered`
- **Cause:** These are FCM errors. `MismatchSenderId` means the FCM credentials uploaded to Sendbird and the `google-services.json` that issued the device token belong to different Firebase projects. `NotRegistered` means the stored token is no longer valid (expired, or the app unregistered from FCM).
- **Fix:** Upload credentials from the same Firebase project as the app's `google-services.json`. Register the device's current token again: the `SendbirdPushHandler` path re-registers on `onNewToken`, and the manual path calls `SendbirdChat.registerPushToken(...)` after `connect`. (source: knowledge/curated/android/cross-cutting/push.md) (source: https://sendbird.com/docs/chat/sdk/v4/android/push-notifications/managing-push-notifications/push-notification-tester) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android/-sendbird-chat/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.push/-sendbird-push-handler/index.html)
- **Cases:** https://community.sendbird.com/t/issue-in-receiving-calls-notifications/565, https://community.sendbird.com/t/fcm-mismatchsenderid/7978, https://community.sendbird.com/t/urgent-fcm-push-alerts-not-being-sent/4020

### Only the most recently used device gets push notifications
- **Cause:** The token is registered as unique, which deletes the user's other tokens. The API reference for `SendbirdPushHandler.isUniquePushToken` says: "If true, all the previously registered token for the current User will be deleted and this token will be the unique one. Default value is false". The manual path has the same switch as the `unique` argument of `SendbirdChat.registerPushToken(token, unique, handler)`.
- **Fix:** Return `false` from `isUniquePushToken`, or pass `unique = false`. Then turn on multi-device support in the dashboard, as Step 6 of the FCM setup guide describes. (source: https://sendbird.com/docs/chat/sdk/v4/android/ref/-sendbird-chat/com.sendbird.android.push/-sendbird-push-handler/index.html) (source: https://sendbird.com/docs/chat/sdk/v4/android/push-notifications/multi-device-support/set-up-push-notifications-for-fcm) (source: knowledge/curated/android/cross-cutting/push.md — Handler-based vs manual token registration)

## Calls

### `onRinging` never fires for incoming calls until the device has dialed once
- **Cause:** An incoming call reaches a device without a live Calls connection through FCM. If no push token is registered with Calls, the FCM message isn't passed to the SDK, or the user isn't authenticated after the app restarts, no ringing event is raised. Chat's `onMessageReceived` is not triggered for calls.
- **Fix:** On every app start, call `SendBirdCall.init(context, appId)`, `SendBirdCall.authenticate(params, handler)` and `SendBirdCall.addListener(id, listener)`. After authentication, register the FCM token with `SendBirdCall.registerPushToken(token, unique, handler)`. In your FCM `onMessageReceived`, pass the message data to `SendBirdCall.handleFirebaseMessageData(...)`, which returns `true` for Calls pushes. Upload the app's FCM credentials in the dashboard. (source: knowledge/curated/android/products/calls.md) (source: https://sendbird.com/docs/calls/sdk/v1/android/features/push-notifications) (source: https://sendbird.com/docs/calls/sdk/v1/android/getting-started/make-first-call) (source: https://sendbird.com/docs/calls/sdk/v1/android/features/direct-call)
- **Cases:** https://community.sendbird.com/t/onringing-is-not-invokded/1947 — community, https://community.sendbird.com/t/incoming-call-alert-not-working-in-android/3760

### Microphone or camera doesn't work during a call
- **Cause:** The Calls AAR declares `RECORD_AUDIO`, `CAMERA` and `BLUETOOTH_CONNECT` in its manifest, but those are runtime permissions. Declaring them does not grant them, and if they are granted only after media starts (for example after entering a group call room), audio and video may stay off.
- **Fix:** Request microphone and camera permissions at runtime, plus `BLUETOOTH_CONNECT` on Android 12 and later, before you dial, accept, or enter a room. (source: sendbird-calls 1.12.5 pkg.aar AndroidManifest.xml)
- **Cases:** https://community.sendbird.com/t/microphone-not-working/2346 — community, https://community.sendbird.com/t/quickstart-call-github-sample-incoming-video-is-not-showing-up/6892 — community, https://community.sendbird.com/t/audio-video-not-working-after-permission-granted/2698

## Upgrading from v3

### v3 code fails to compile after moving to Chat SDK v4
- **Cause:** v4 renamed and repackaged the SDK. The main class `SendBird` is now `SendbirdChat`, `SendBirdException` is now `SendbirdException`, and classes moved into new packages such as `com.sendbird.android.channel`, `com.sendbird.android.message`, and `com.sendbird.android.handler`. `ChannelHandler` is split into `BaseChannelHandler`, `GroupChannelHandler`, and `OpenChannelHandler`. Params classes are split into create and update params (for example `GroupChannelParams` into `GroupChannelCreateParams` and `GroupChannelUpdateParams`), builders became constructors, getters and setters became properties, and some methods were replaced (for example, `addUsers` on the create params by the `users` property).
- **Fix:** Follow the migration guide: remove every `import com.sendbird.android.*` line, replace `SendBird` with `SendbirdChat` and `SendBirdException` with `SendbirdException`, then add the v4 imports and let the IDE optimize them. On a Mac, the guide's migration script does the first three steps. (source: https://sendbird.com/docs/chat/sdk/v4/android/getting-started/migration-guide) (source: https://sendbird.com/docs/chat/uikit/v3/android-view/miscellaneous/migration-guide)
